🧮 Food Cost

Work out a product's real cost from its recipe: for each ingredient, enter the package size you bought, what you paid for it, and how much of it goes into this recipe. Saving updates the product's Cost (used everywhere Profit is shown).

Loading...

Editing an ingredient's package size/unit/price here updates every saved recipe that uses it (by name) and recalculates that product's Cost automatically. Removing one only stops it being suggested for new entries — it doesn't touch recipes that already used it. Tick "Per pack" for packaging-type ingredients (e.g. a pouch or box used once per sold pack) so their cost is charged straight to Cost per pack instead of being diluted across the whole batch — this applies to every recipe using that ingredient.

🗄️ Monthly Security Backup

It's a new month — have you exported a backup copy of your data from Supabase this month?

In the Supabase SQL Editor, run this once, then click Export → CSV on the result (a single file with every table):
select 'orders_history' as table_name, to_jsonb(t) as row_data from orders_history t union all select 'users', to_jsonb(t) from users t union all select 'products', to_jsonb(t) from products t union all select 'admin_messages', to_jsonb(t) from admin_messages t union all select 'app_settings', to_jsonb(t) from app_settings t;
Also go to Storage → product-images, select all files and download them (product photos aren't included in the query above).

Ingredient names you've used before will suggest their saved package size/unit/price — pick one to fill it in automatically.

Use "kg" for weight-based recipes, or "unit" for recipes sold as whole items (e.g. this batch makes 16 unit, sold in packs of 1 unit). Leave "batch yield" blank (or 0) if the whole batch is sold as one unit.
